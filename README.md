## 🏁 Mission Accomplished: 50/50 Days Completed!
This repository is the result of a 50-day "digital detox" where I rebuilt my coding intuition by banning AI-generated code and focusing on manual logic, official documentation, and engineering fundamentals.

## 🏗️ Final Architecture: The Portfolio API Hub
At the end of this journey, I didn't just have 50 scripts; I built a Dockerized API Ecosystem.

Central Gateway: A FastAPI hub integrating weather, currency, and utility services.

Security Layer: API Key authentication for all endpoints.

Infrastructure: Fully containerized environment with Docker Compose and automated health monitoring.

Asynchronous Core: Non-blocking logic using httpx and aiohttp.

## 🎯 The Concept
I'm a graduate Data Science student, and I've noticed a problem: I'm relying on AI way too much. Tools like ChatGPT are great, but I started feeling that my core coding skills were getting "rusty." 

**Project 50** is my personal 50-day challenge to fix this. It's a "digital detox" to rebuild my logic and muscle memory by solving tasks manually every single day.

## 🚫 The Rules
1. **Zero AI for Code:** No ChatGPT, Copilot, or Claude for writing logic.
2. **Back to Docs:** I use only official documentation and Google/StackOverflow for research.
3. **Manual Commits:** One day, one task, one manual commit. No copy-pasting.

## 🧠 The Approach
To be 100% transparent: I used AI to help me structure this roadmap and generate task descriptions. However, **every single line of code** in this repository is written by me from scratch, based on my own logic and documentation research.

## 🛠️ How to Start Your Own #Project50 Challenge
If you feel that AI is writing code faster than you can understand it, this guide is for you. Here is the blueprint to reclaim your logic:

1. 📂 Set Up the Structure
Don't just code in one messy folder. Create a clear roadmap with phases. This keeps you motivated and shows progress.

```
Phase 1: Core Logic (algorithms, loops, math).
Phase 2: System (files, paths, OS).
Phase 3: Architecture (OOP, Design Patterns).
Phase 4: Integration (APIs, Databases, Libraries).
Phase 5: Deployment (Docker, CI/CD, Cloud).
```

2. 🚫 The "AI-Free" Protocol
The goal isn't to be productive; it's to be capable.
```
Research, don't ask: Use Google or StackOverflow to find how something works, but write the logic yourself.

Doc-First Approach: Always keep the official documentation (Python, FastAPI, Docker) open in a tab.
```

3. 🧪 Small Wins Every Day
```
Don't try to build a startup on Day 5. Solve a small, specific problem.

Bad goal: "I will build a weather app."

Good goal: "Today I will successfully parse a JSON response from a weather API without using AI."
```
4. ⚓ Commit Discipline
```
One task = one commit. Write meaningful commit messages. It builds a history of your thought process.
```

5. 🐋 The Grand Finale
```
On the final days, don't just stop. Integrate. Connect your separate scripts into one ecosystem. This forces you to think about how different modules interact.
```
